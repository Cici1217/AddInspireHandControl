# G1 准备姿态

这些 txt 文件只包含 **29 个身体关节角度，单位 rad**。不包含机器人在世界中的位置、手指或场景物体，与 MuJoCo keyframe 无关。

控制台的「准备姿态（可选）」提供三个选项，也可填写自定义 txt 的项目相对路径，例如 `gear_sonic/data/poses/g1/box_ready.txt`；项目外文件仍可使用电脑绝对路径：

- 默认（原版 SONIC 流程）：不指定准备目标。
- 双臂前抬（`arms_raised.txt`）：双手向前抬到胸前，用来直观看到开始控制后的变化。
- 盒子任务（`box_ready.txt`）：双臂靠近身体、双手位置较低的已有任务预设。

原 `default_stand.txt` 文件保留，需要时仍可通过自定义文件选择；它不修改原版 SONIC 的初始化角度。

初始化始终沿用原版 SONIC 的关节姿态；初始化本身仍会运动。自定义准备姿态只在开始 SONIC 控制后执行：单独身体控制按 `]`，PICO / VLA 按第一次 Enter。开始控制后，腰和双臂从当前反馈姿态用约 3 秒平滑过渡到准备目标；SONIC 始终用腿部维持平衡。29 维文件沿用身体关节顺序，其中腿部角度不作为固定站立目标，当前准备功能使用腰和双臂的 17 个角度。

更换准备姿态后，重新启动身体程序及对应的遥操 / VLA 入口；不会修改已经运行的身体程序。

文件顺序：

| 下标（从 0 开始） | 关节顺序 |
| --- | --- |
| 0–5 | 左腿：hip_pitch、hip_roll、hip_yaw、knee、ankle_pitch、ankle_roll |
| 6–11 | 右腿：同上 |
| 12–14 | 腰：yaw、roll、pitch |
| 15–21 | 左臂：shoulder_pitch、shoulder_roll、shoulder_yaw、elbow、wrist_roll、wrist_pitch、wrist_yaw |
| 22–28 | 右臂：同上 |

复制一个示例文件，修改角度，再选择「自定义姿态文件」。支持空格或换行分隔；不支持注释。程序检查数量、有限值和关节限位。没有选择时保持原来的启动流程。

- 身体控制：初始化完成后按 `]` 让 SONIC 接管并进入准备姿态；在行走/站立模式保留准备目标，新的上身参考或动作回放接管后使用新的参考。
- PICO：第一次 Enter 进入准备姿态；确认站稳、按现场方式释放支撑并摆好人体标定姿势后，第二次 Enter 开始遥操。程序要求腰和双臂误差在 0.15 rad 内连续保持 0.5 秒。
- VLA：第一次 Enter 进入站立准备，第二次 Enter 确认开始推理；同样先检查准备姿态到位。

真机需要部署更新后的 `run_body.sh` 和重新编译的 `g1_deploy_onnx_ref`。控制台会把已校验的角度传给 G1，不需要再手动复制 txt 到 G1。旧版二进制会被启动脚本拒绝；本地编译和仿真检查不代表已在真机验证。

2026-10-27：G1 已完成部署，用户已确认身体控制真机测试通过。`low_latency` + `table_box` 的仿真中，`box_ready` 已通过键盘和网络两条启动路径的到位检查；`arms_raised` 在本次保留支撑 4 秒后释放的仿真流程中出现失稳，不能据此宣称该组合已通过仿真验收。此现象与用户的真机测试结果分别记录，未因此修改用户的姿态预设或真机控制参数。

命令行原生参数为 `--ready-pose "29 个空格分隔的角度"`。原生程序的 `--check-ready-pose "29 个角度"` 只检查参数，不初始化 DDS 或发送机器人命令。旧 `--sim-initial-pose` 仍只允许仿真，不能和新参数同时使用。`default_angles` 仍保持策略原来的数值。
