# 本地网页控制台

控制台的源码、命令入口、默认工作目录和输出都属于当前 checkout，不需要导入旧项目的 `extensions/inspire`。

## 启动

```bash
# 在本项目根目录执行
python3 -m gear_sonic.scripts.run_console
```

浏览器打开 <http://127.0.0.1:8765>。系统 Python 3.10+ 即可启动网页，无需 npm。网页顶部显示实际加载代码的目录；实验程序分别使用所配置的仿真、遥操、采集环境。

上方大按钮选择“仿真 / 真机”，当前选项显示蓝色。右上角“网页服务正常”只代表浏览器与本机网页服务通信正常，机器人和 PICO 连接状态仍查看对应终端；“网页服务断开”表示页面暂时无法更新状态。

默认配置保存在项目内的 `configs/console/profiles.json`，不提交到 Git。首次启动新版时，如果这里还没有配置，会从原来的 `~/.config/gear-sonic-newbranch-console/profiles.json` 导入，保留原文件；之后以项目内的配置为准。可用 `--port 8766 --state-dir configs/another-console` 修改端口和存储位置。页面沿用已有的当前配置，修改通过校验后自动保存。

项目目录默认填 `.`，代表运行这份控制台代码所在的项目根目录，与启动命令时终端所在的位置无关。项目内路径保存为相对路径，例如：

| 内容 | 配置路径 |
| --- | --- |
| 仿真 Python | `.venv_sim/bin/python` |
| 遥操 Python | `.venv_teleop/bin/python` |
| 采集／回放 Python | `.venv_data_collection/bin/python` |
| Inspire 手配置 | `gear_sonic/devices/inspire/assets/hand_config.yaml` |
| 准备姿态 | `gear_sonic/data/poses/g1/box_ready.txt` |
| 光学手标定 | `outputs/inspire_calibrations/pico_hands.json` |
| 录制数据 | `outputs/datasets/sim/任务名` 或 `outputs/datasets/real/任务名` |
| 微调模型 | `outputs/checkpoints/finetuned/模型名` |
| 相机代码传输来源 | `gear_sonic/camera` |

旧配置中的项目内绝对路径会转换为相对路径；模型弹窗、数据集选择和准备姿态预设也使用相对路径。执行命令时统一解析为当前项目的实际路径，因此切换步骤工作目录不会改变文件定位。命令详情和历史执行日志仍会显示执行时的实际路径，便于检查。

Isaac-GR00T、其推理 Python 环境、TensorRT 和 XRoboToolkit 属于外部依赖，保留实际安装路径，由每台电脑自行配置；G1 路径仍属于机器人。迁移项目时不需要逐项修改项目内路径，但 Python 环境需要在新电脑重新安装，外部依赖和 G1 连接需要重新确认。

## 使用

新同学先打开「公共配置」，按顶部的四项说明完成本机环境、仿真与模型、PICO / VLA 外部依赖、实验室 G1 配置。仿真和真机配置同时保留，不需要在两个项目之间切换。

- 项目内的 Python 环境、数据、模型、场景和手配置预填相对路径；已有环境可以填写自己的位置。
- TensorRT、XRoboToolkit、Isaac-GR00T 安装目录支持弹窗选择。GR00T checkpoint 也可在公共配置选择，06 的模型选择同步使用这项配置。
- G1 部署根目录、身体／手部启动文件、相机目录及 Python 都在公共配置中填写。修改部署根目录后，仍位于原目录内的子路径随之更新；已单独配置到其他目录的路径保留。相机或身体、手部子目录也会联动自己的启动文件。路径仍需与机器人上的实际文件一致。
- 点击「检查本机配置路径」后显示找到和缺少的文件，点击结果名称可跳到对应配置。该检查不连接 G1，也不启动程序；不会把本机文件存在当作环境或真机已就绪。光学手标定缺失时显示首次遥操的标定提示。
- 顶部「安装与检查」提供仿真、PICO、采集／回放、VLA、G1 五个环境入口；各环境配置组也有「查看安装与检查步骤」。选择后在公共配置页内展开实际命令和执行按钮，结果显示在运行终端。选择环境不会自动执行安装。07 复用同一套执行步骤。G1 检查会核对已配置的目录、身体／手启动文件、bridge.env、相机代码和依赖，不启动机器人控制。

侧栏只保留已接入的 **01–07**。未完成的 08 场景重建、09 训练评估入口和配置字段已移除；旧配置加载时自动清理这些字段。

公共配置各组下方的「下载／获取说明」提供官方链接、可复制命令、保存位置和对应配置项。命令由用户在终端执行；页面只展示说明。下载项包括：

| 内容 | 获取方式 | 放置位置／填写项 |
| --- | --- | --- |
| uv / Python 3.10 | [uv 官方安装](https://docs.astral.sh/uv/getting-started/installation/)，再运行 `uv python install 3.10` | `uv python find --no-project 3.10` 输出填入基础 Python |
| 仿真、PICO、采集 Python 依赖 | 公共配置选择对应环境，创建环境并联网安装 | `.venv_sim/`、`.venv_teleop/`、`.venv_data_collection/` |
| SONIC release 和 planner | [GEAR-SONIC](https://huggingface.co/nvidia/GEAR-SONIC)，项目根目录运行 `uv run --no-project --with huggingface_hub python download_from_hf.py` | `gear_sonic_deploy/policy/release/`、`gear_sonic_deploy/planner/target_vel/V2/` |
| SONIC low_latency | 同上命令加 `--low-latency` | `gear_sonic_deploy/policy/low_latency/`；填 VLA 的 SONIC 模型前缀和观测配置 |
| 桌面 TensorRT | [NVIDIA 下载页](https://developer.nvidia.com/tensorrt/download/10x)，Linux x86_64、10.13.x TAR，选择匹配 CUDA 的包；当前桌面验证 10.13.3 | 解压到自选工具目录，将含 `include/`、`lib/`、`bin/` 的根目录填入 TensorRT 目录 |
| XRoboToolkit PC Service | [v1.0.0 发布页](https://github.com/XR-Robotics/XRoboToolkit-PC-Service/releases/tag/v1.0.0)，按 Ubuntu 22.04／24.04 选择 amd64 DEB；页面分别提供命令 | 确认 `/opt/apps/roboticsservice/run3D.sh`，填写服务目录和启动脚本 |
| PICO 客户端 | [v1.1.1 发布页](https://github.com/XR-Robotics/XRoboToolkit-Unity-Client/releases/tag/v1.1.1) 下载 `XRoboToolkit-PICO-1.1.1.apk` | 安装到头显 |
| Isaac-GR00T | 下述对应源码版本＋本项目提供的 RTC 补丁 | 自选项目外目录；其 `.venv/bin/python` 填 PolicyServer Python |
| 原始 GR00T N1.7 | [官方模型](https://huggingface.co/nvidia/GR00T-N1.7-3B)，页面提供 `hf download` 命令 | `outputs/checkpoints/pretrained/GR00T-N1.7-3B/` |
| 葡萄等微调 checkpoint | 从实验室获取完整模型文件夹；此处没有公开下载地址 | `outputs/checkpoints/finetuned/<模型名>/`；06 选择具体 checkpoint |
| 手模型、场景、准备姿态 | 随实验室这份项目提供；Git 获取的版本需要拉取 LFS 文件 | 保留项目原有目录结构 |
| 光学手标定 | 首次 PICO 遥操按提示生成 | `outputs/inspire_calibrations/pico_hands.json` |

原始 N1.7 是预训练起点，不能当作已经学会实验室任务的 G1/Inspire checkpoint。G1 已部署的身体、手桥接和相机程序由实验室提供；新电脑填写机器人现存路径，公共配置中的相机传输不等于部署全部 G1 程序。

**Isaac-GR00T 的 RTC 兼容性：** 当前项目使用官方提交 [`65cc4a192e6d084650d97747308b6a8deb790722`](https://github.com/NVIDIA/Isaac-GR00T/commit/65cc4a192e6d084650d97747308b6a8deb790722) 加实验室 RTC 策略补丁。补丁随项目保存在 [isaac-groot-rtc.patch](../../../external_dependencies/patches/isaac-groot-rtc.patch)，包含策略改动和原有对应测试。它从本机已验证版本导出，在临时目录应用后与该版本的两个文件逐字一致；未改动正在使用的外部 Isaac-GR00T。

公共配置的「VLA 运行环境 → 下载／获取说明」给出克隆固定版本、应用补丁、运行官方 `uv sync --python 3.10` 的完整命令。该命令只用于新目录，遇到已存在的目标目录会停止。安装前按源码部署指南准备 CUDA 和 FFmpeg；安装后在公共配置完成依赖检查，再运行 06 的模型检查。这里没有在新电脑上重新安装全部 GPU 依赖，也没有重新验证抓取任务。

1. 先选功能，再在功能内选仿真或真机。
2. 首次或换机器时打开左侧“公共配置”：按“本地电脑”和“G1 机器人”分区填写。电脑区配置本机项目、Python、模型和连接端口；G1 区配置 SSH 连接及机器人上的程序、相机路径。路径属于各自机器。
3. 功能内的“本次配置”只放当前操作参数，如手型、动作目录、采集时长/条数/深度/保存位置，或手指动作/目标角度。点击标题可收起或展开，收起不改变参数。项目、解释器、模型、端口等统一从左侧“公共配置”修改，任务页不再显示环境链接。
4. 每个步骤的“操作说明”写实际操作和按键；“命令与说明”解释所启动程序及主要参数的作用，并列出实际命令、执行机器、工作目录、环境和输出位置。每步可独立展开并复制命令。参数变更会更新预览，修改期间不能执行旧命令。
5. 点击“执行此步”，右侧终端自动打开。完成该步骤后，手动点击下一个步骤；没有按顺序自动启动。
6. 本控制台已启动并确认就绪的相同服务会自动复用，无需勾选前置服务。未就绪或配置不一致时仍阻止启动；外部终端启动的服务不自动视为就绪，可复制后续命令到外部终端执行。
7. 配置修改自动保存到本机，刷新后继续使用。公共配置页显示保存状态；参数无效时不保存，失败时显示“配置未保存”。换电脑后检查公共配置的机器路径，再在公共配置展开对应环境的安装与检查步骤。

界面采用导航、配置/步骤、运行终端三个区域。参考 [Foxglove 面板](https://docs.foxglove.dev/docs/visualization/panels) 和 [RViz 停靠窗口](https://github.com/ros2/rviz/blob/rolling/rviz2/doc/index.rst)，使用紧凑工具栏和可调整的分区。

终端固定在右侧大面板，拖动它的左边界调整宽度，双击边界恢复默认；宽度只记在当前浏览器。每个进程一个标签；可全屏、隐藏面板，或从左侧“运行终端”和步骤旁“查看终端”再次打开。窄屏以大面板覆盖显示，点击“隐藏”返回功能页。Enter、确认就绪和停止按钮作用于当前显示的进程。向上翻看日志时保持位置，“最新日志”恢复查看末尾。刷新网页会重新显示本服务仍在运行的进程。

“停止 Ctrl+C”停止当前进程；“停止全部”沿用原来的顺序停止。命令和路径放在步骤详情中，本次配置可折叠。

点击终端标签的“×”或“停止并关闭”：运行中的先发送 Ctrl+C，确认进程退出后才关闭。停止中保留日志，等待退出；已经停止、完成或失败的终端直接关闭。刷新网页后已关闭的标签不会再出现，日志文件仍保留。“隐藏”只改变显示，程序继续运行；停止并关闭进程用标签的“×”。

操作说明收在左侧步骤的“操作说明”中。右侧不再显示大段启动提示，标题、状态及输入/停止按钮使用固定高度的小工具栏；日志与控制区使用余下空间。黑色区域是日志，点击终端按钮即可发送输入，不用在日志区打字。网页根据程序输出显示当前启动按钮，不会自动确认部署或发送运动按键。

第一个入口“身体控制”独立启动 SONIC 键盘控制。仿真末端执行器可选 **Inspire Hand / Dex3**，默认 Inspire；真机固定 **Inspire Hand**，不提供 Dex3 选项。仿真模型与身体程序一起切换；Dex3 不加载 Inspire YAML。切换手型前先停止现有身体和场景程序，再执行新的两步。动作回放使用同一选择项。

设备列表与动作控件读取本地注册文件。手指、PICO、采集可选择已注册的 Inspire 或仿真平行夹爪；Dex3 只出现在已支持的身体、场景和回放功能中。切换功能时，页面会选择当前功能支持的设备；仿真与真机分别保存选择。当前真机注册仍只有 Inspire。

“公共配置 → 末端执行器注册”设置注册目录；可选部署 JSON 指定后端、安装位置和模型绑定。目标控件按安装位置与动作通道生成：Inspire 左右手各六通道，夹爪为一个 `tool.width`，单位米、范围 0–0.08。超限时执行按钮停用。后续设备的接入步骤见 [末端执行器指南](../../../gear_sonic/utils/hand_control/README.md)。

独立夹爪不启动 G1/SONIC 身体程序。手指控制直接运行本地仿真，场景入口可单独查看模型。夹爪采集可选自动测试动作或 PICO，程序为每条数据启动仿真、记录实际反馈和 RGB 图像，结束后关闭该仿真并导出 LeRobot，原始轨迹保留在 `raw/`。原 Inspire 全身采集继续只读录制，结束录制不停止已运行的遥操。每条录制先以“未标注”保存，随后在运行终端选择“本条成功”“本条失败”或“暂不标注”；每条结果独立保存在 `meta/recordings/episode_XXXXXX/end_effector.json`，并同步更新批次清单及该条原始数据元信息。

**仿真**按以下顺序：

1. 选“身体控制 → 仿真”，不勾选“不显示仿真窗口”，先执行仿真步骤。
2. 电脑弹出的 MuJoCo 窗口显示机器人后，先不按 `9`。回到网页仿真终端，点“确认仿真已显示”。看起来站着只表示场景已打开。
3. 手动点击 SONIC 身体步骤的“执行此步”。看到 `Proceed with deployment? [Y/n]`，点“确认部署 y↵”。按钮会发送 `y` 并回车；完整的 `yes` 不被脚本接受，直接回车也可确认。
4. 同一身体终端看到 `Init Done`，点“进入控制 ]”；看到 `CONTROL state`，点“站立 / 行走 ↵”。
5. 看到 `motion name is planner_motion`，保持支撑再等至少 3 秒。鼠标点击电脑的 **MuJoCo 仿真窗口**，再按键盘 **`9` 一次**释放支撑。网页身体终端的“减速 9”不负责释放支撑。
6. 观察稳定站立后，回网页身体终端点“确认已站稳”。确认后可手动执行后续步骤。
7. 走动时，先点右侧“慢走 1”，再点“前进 W”；点“停步 R”停止移动。手指测试则保持站立，执行手指步骤。

**真机**使用“身体控制 → 真机”。吊架保持保护；当前 G1 入口不询问部署确认，直接等 `Init Done`，依次点“进入控制 ]”“站立 / 行走 ↵”。看到 `motion name is planner_motion` 后观察站稳，按现场操作逐步让双脚承重，再点“确认已站稳”。真机不按 `9` 释放吊架。

默认组 `1` 慢走、`2` 走路、`3` 跑步；`N/P` 切换四个动作组，页面显示对应的全部动作按钮。点“启用键盘控制”后可直接用键盘；填参数时不接收控制键，切换终端、隐藏面板、网页失去焦点会自动停用键盘接收。**松开方向键不会立即停止移动，停止移动按 R**。按钮始终可点击。

| 按键 | 行走模式 | 动作回放模式 |
| --- | --- | --- |
| Enter | 切到动作回放，保持参考动作首帧 | 切到行走 / 站立 |
| N / P | 下一组 / 上一组 | 下一动作 / 上一动作，回到首帧 |
| 1–8 | 选择当前组内动作（以页面列出的有效编号为准） | 不使用 |
| W/S、A/D、逗号/句号 | 前后、斜向、侧向移动 | 不使用 |
| Q / E | 调整行走朝向 | 调整参考朝向 |
| J / L | 调整参考朝向 | 不使用 |
| 9 / 0、- / = | 减速/加速、降低/升高蹲姿 | 不使用 |
| R | 停止移动 | 回到首帧并停止播放，机器人姿态随之重置 |
| T | 继续播放当前运动 | 播放到末尾 |
| I / Z | 重设朝向 / 切换编码 | 同左 |
| F / H | F 查询温度 | H 查询温度 |
| O | 退出控制 | 退出控制 |

### 05 自己录制数据的回放（G1＋Inspire）

选择数据集和 Episode，再选“身体回放方式”：

- **SMPL 人体参考**：读取该条录制的 SMPL/VR 人体动作，经过 SONIC 控制身体。
- **实测关节角参考**：读取该条录制新增的 `sonic_reference/episode_编号/`，将实测关节角、速度和身体朝向作为 G1 参考交给 SONIC。双手仍使用同条录制的提交目标，按原始采样时间对齐。

两种方式都同步回放身体和双手。缺少 `sonic_reference` 的旧录制选择第二种会明确报错，不会自动改用 SMPL；不回写或转换已有录制。仅保存完整仿真状态的旧数据继续走场景查看，不显示身体参考选择。

数据集始终选电脑上含 `meta/info.json` 的目录，无需进入 CSV 子目录或复制到 G1。选择播放目标（仿真／真机）和播放帧数；`0` 帧表示整条，150 帧为前 3 秒。公共配置的“采集与回放运行环境”指定读取 Parquet 的 Python。

SONIC 自带动作仍在“01 身体控制”的原生键盘流程中使用，05 不再提供单独的自带 / CSV 动作入口。

先停止已有 PICO、手指动作和身体控制，再逐步执行检查、场景或桥接/转发、身体、回放。看到 `Init Done` 后，在**回放终端**点击“启动站立（Enter）”；身体终端不按 `]` 或 Enter。等 `REPLAY_STANDING` 并确认站稳，仿真在 MuJoCo 窗口按一次 `9` 释放支撑，真机按现场操作让双脚承重、保留吊架保护。随后在回放终端点击“开始回放（Enter）”。无需头显、相机或 G1 上的数据副本。

回放终端显示帧数和进度；正常完成后切回 SONIC 站立，释放手部会话。中断或反馈失效会停止此次回放并发送身体停止。结束身体进程前先恢复支撑，再使用身体终端的 `O`。复用运行中的终端时，不要同时启动 PICO 或其他手动作。

实现集中在 `gear_sonic/devices/inspire/replay.py`，通用入口为 `python -m gear_sonic.scripts.replay_episode`，通过设备注册的 `integration.dataset_replay` 加载。只读取原记录，不覆盖或转换源数据：

- 支持旧项目 v3、新分支 v4 的完整 G1＋Inspire LeRobot episode；默认读取身体 SMPL/VR 参考，实测关节角方式需要额外保存的身体参考和采样时间。
- SMPL 使用 SONIC Pose v3，实测关节角参考使用原生 Pose v1 / G1 encoder；两种均通过 Decoder 控制身体，均不直接发送关节电机命令。手部使用原 Adapter/Driver，目标 50 Hz。
- 检查 50 Hz 时间、关节顺序、有限值、动作限位及保存的动作映射；IP、串口和模型文件位置属于部署参数，允许不同。仅手部数据、未完成数据和不同动作空间会被拒绝。
- 保留启动时实测手姿、原动作限位/速度/碰撞检查、串口协议和反馈新鲜度检查。MuJoCo 反馈按原驱动的状态合同读取，不把软限位产生的微小实测偏差当作越界命令。
- 每次执行将来源哈希、目标配置、已播帧数、频率和错误保存到 `outputs/replay_runs/`。手目标若受现有限速／碰撞约束调整，日志会显示 `REPLAY_LIMITED`，报告保留调整帧数与最大目标差。仿真与真机物理条件不同，跨环境回放仍需目标环境验证。

在已配置的数据 Python 环境中，以下命令只检查数据；增加 `--execute` 才会连接控制，并需要两次 Enter：

```bash
python -m gear_sonic.scripts.replay_episode outputs/datasets/sim/任务名 --target sim --episode 0 --frames 150

# 同一条数据，改用实测关节角参考；仍然只检查，不连接控制。
python -m gear_sonic.scripts.replay_episode outputs/datasets/sim/任务名 --target sim --episode 0 --body-reference joints
```

真机选择 `--target real --hand-config gear_sonic/devices/inspire/assets/hand_config.yaml`，沿用现有 SSH 转发和 G1 身体程序。`--auto-start` 仅供本地仿真测试，真机禁止跳过操作确认。

第 4 / 5 页的「查询 IP（可选）」默认收起，展开即可复制命令，在需要查询的电脑或 G1 终端执行：


仿真等身体终端显示 `CONTROL state`、机器人已经跟随，保持支撑再等至少 3 秒，然后点击 MuJoCo 窗口并按 `9` 一次。真机观察站稳并跟随后，让双脚逐步承重、吊架保持保护。遥操正常后，录制终端看到 `Capture ready` 再点“开始录制（Enter）”。

## 数据保存与公共配置初始化

数据采集页上方显示「录制与回放位置」，列出相对项目根目录的仿真、真机数据路径，以及当前录制来源。「查看已录制数据」直接进入数据集回放选择。PICO 遥操作页保持原样。

`sim` / `real` 只区分录制来源。普通 PICO 身体与双手录制可以从同一目录选择仿真或真机回放，无需搬动数据；切换回放目标不改变所选数据目录。回放列表显示实际读取路径。仅保存仿真场景状态的数据仍只支持仿真查看。

1. 左侧「公共配置 → 本地电脑 → 项目目录」默认保留 `.`，自动使用当前代码所在项目；需要操作其他 checkout 时再填写其目录。
2. 数据固定保存在项目内的 `outputs/datasets/sim/` 或 `outputs/datasets/real/`；公共配置的「数据与输出目录」只显示位置，无需填写。
3. 点击「初始化目录」。只创建缺少的目录，已有文件保留，不连接 G1。新电脑初始化页的「初始化本机输出目录」执行同一操作。
4. 在「04 数据采集」选择仿真或真机、填写数据集名称。页面显示最终保存路径；目录自动按来源选择，无需每次修改。

```text
outputs/
├── datasets/
│   ├── sim/名称/        # 仿真录制，包含 data、videos、meta 等
│   └── real/名称/       # 真机录制，仍保存在电脑
├── console_logs/            # 网页进程日志
├── inspire_calibrations/    # 手部标定
└── replay_runs/             # 回放执行记录，不是新采集的数据集
```

04 填写的名称直接作为文件夹名；同批多条录制在这个文件夹内按 Episode 0、1、2…保存；再次启动同名批次才追加 `_001`、`_002`，不覆盖已有文件。保存的是 LeRobot 格式，包含视频、状态、控制数据及元数据。05 按文件夹名列出完整数据集并自动更新，可筛选仿真／真机来源；保留「检查录制数据」，检查通过后回放。仿真/真机按钮决定在哪里播放，与录制来源独立。旧录制不搬动，仍可展开手动填写旧目录。

命令行批量录制也按来源自动选择默认目录：`capture_session --sim` 保存到 `outputs/datasets/sim`，不加 `--sim` 保存到 `outputs/datasets/real`。显式 `--output-root` 继续使用原样指定的父目录；单条录制的 `record_pico_lerobot --output` 也保留显式路径。

## 采集与深度

网页采集每条开始前都等待操作者在录制终端按 Enter。先启动 PICO 遥操，准备好后点“开始录制（Enter）”；随后等待配置的秒数，录制指定实际时间窗口。条数 0 表示持续采集；每条保存后暂停，等待操作者在运行终端选择“本条成功”“本条失败”或“暂不标注”，标注后再次等待 Enter，准备好场景再开始下一条。任务结果不在开始前预填，也不整批共用。等待标注或结束录制都不停止遥操；等待标注时停止程序，已保存的数据保留为“未标注”。

一批录制保存一个 LeRobot 数据集，内含多个 Episode：`outputs/datasets/sim/名称` 或 `outputs/datasets/real/名称`。同批逐条追加 Episode；再次启动同名批次时使用 `名称_001`、`名称_002`……跳过已有目录，同名前缀同时只允许一个录制器写入。Ctrl+C 取消当前未完成条，保留已提交条。采集不到 40 个有效同步帧会失败；不会无限延长时间补帧。50 Hz 是名义采样频率，实际时间与丢帧写入 timing/summary。

原 `record_pico_lerobot --frames 600` 仍直接启动单条录制，默认关闭深度；新增 `--seconds`、`--wait-seconds`、`--depth off|required|auto` 和 `--camera-port`，不改变遥操。

开启深度时：

- 仿真使用 `run_sim_loop --enable-depth-publish`，发布同一物理状态渲染的 RGB 和深度。
- 真机需要 G1 上运行本版本相机代码及 RealSense SDK；页面中的 G1 相机路径需填写真实部署位置。仅有硬件深度能力不足以启用录制，RGB-only 输入会明确报错。
- 深度无损保存为 `depth/episode_000000/frame_*.png`（uint16），`meta/depth/episode_000000.json` 保存比例、内参、外参及每行动作到深度帧的对应关系。重复收到同一深度帧只保存一次图片。
- RealSense 保留原生 RGB/深度网格和 depth-to-color 标定；相机到世界仍需要实际标定。仿真另带模拟相机到世界的逐帧位姿，并明确标记模拟来源。
- 深度为旁路文件，不混入原 41 维状态、手部目标或 RGB 视频特征。能录制 RGB-D 不代表自动场景重建已经完成。

关闭“保存深度”时，在解码前跳过深度通道，兼容旧版 RealSense 服务携带的 JPEG 深度消息，只录制 RGB。开启深度或使用 `--depth auto` 时仍严格检查无损编码与标定，不会把旧 JPEG 当作深度保存。

### 自动保存与数据选择

采集时，仿真／真机按钮决定数据实际来源，固定保存到项目内 `outputs/datasets/sim/名称` 或 `outputs/datasets/real/名称`，重名时自动编号。网页不再提供保存目录覆盖；旧配置中的自定义输出目录不再用于新录制，旧数据保留原处。

回放页进入时及停留期间自动扫描 `outputs/datasets` 中的完整数据集，按文件夹名显示，无需点击刷新。可筛选采集来源、选择数据及 Episode，也可手动填写旧的外部目录；「检查录制数据」仍需执行。普通 v3/v4 遥操录制仍使用 SONIC 和 Inspire 动作回放，目标仿真／真机与来源独立。

带 `meta/simulation_replay.json` 的物理仿真录制会自动显示「检查录制数据 → 仿真场景回放」两步，使用保存的完整场景和状态，不启动控制服务。此类型只支持仿真查看。状态回放、控制指令回放不会互相冒充。

## 自定义准备姿态

身体控制、PICO、数据采集与 VLA 页面共用「准备姿态（可选）」。可以选原版默认流程、双臂前抬、盒子任务准备姿态，或自定义 29 维角度文件。姿态与场景无关；选择预设会替代旧的 VLA 仿真初始姿态与 keyframe。

初始化沿用原版 SONIC 姿态。按 `]`（身体控制）或第一次 Enter（PICO / VLA）开始 SONIC 控制后，才进入腰和双臂准备目标，腿部继续负责平衡。PICO 开启此功能时增加一次 Enter：先进入准备姿态，确认站稳并按现场方式释放支撑，再按 Enter 开始人体标定和遥操。VLA 沿用两次 Enter，并在开始前检查目标误差。手指依旧独立控制。

详见 `gear_sonic/data/poses/g1/README.md`。不选择准备姿态时保持原流程；新部署的机器人需要同时更新启动脚本和身体可执行程序。
